# 广东电力市场行情采集器

每天自动抓取广东电力交易中心的公开行情数据，落地成结构化数据。

**已实测跑通**：2026-10-08 首次运行，成功采集到 2026-10-07 的 24 点逐时价格、21 个地市的峰谷电价、中长期年度交易数据，以及 5 个场址的逐小时气象数据。

## 二、为什么必须用浏览器而不是直接调接口

这是本次踩坑的核心，说清楚免得你走弯路：

**坑一：网关会拒绝你** —— 直接 `requests.get` 接口路径，返回 **400 空 body**。看着像路径写错了，实际是网关对「未注册路由」的统一响应，会让人误以为在猜路径上出了问题。

**坑二：真正的路径在 JS 包里** —— 从 `umi.560423f0.js` 里挖出了路由表，才发现真实前缀是 `/portal/xhr/sso-portal/...` 和 `/portal/xhr/sso-disclosure/...`，中间那层微服务名（`sso-portal`）是必须的。

**坑三：URL 必须带 WAF 签名** —— 所有合法请求都要带形如 `?HdKGccbL=0cZY9RGlqEhkbWTeQGbI3QBp8vGY4...` 的查询参数。这个 token 由页面 JS 动态生成（每次不同），**外部无法稳定构造**。

**结论**：与其逆向 token 生成算法（脆弱且易被封），不如**让真实浏览器去访问，我们监听它的 XHR 响应**。这是最稳的方案，也是本项目的做法。

> 若哪天接口改了，改 `collector.py` 顶部的接口常量即可，不用动架构。

## 四、怎么用

### 4.1 本地跑

```bash
cd gd_price_collector

# 安装依赖
pip install requests playwright
playwright install chromium

# 采集全部
python3 src/collector.py --export

# 只采行情（不采气象）
python3 src/collector.py --only price --export

# 显示浏览器窗口（调试用，能看到页面在做什么）
python3 src/collector.py --headed
```

### 4.2 云服务器部署

```bash
# 上传整个 gd_price_collector 目录到服务器，然后：
sudo timedatectl set-timezone Asia/Shanghai   # 确保时区正确
sudo bash deploy.sh
```

部署脚本会自动完成：装依赖 → 建虚拟环境 → 装 Chromium → 写 crontab → 跑一次自检。

**定时任务安排**（部署脚本已写入）：

| 时刻 | 任务 | 理由 |
|---|---|---|
| 06:10 | 气象 | 拿历史+7日预报 |
| 09:10 | 行情 | 覆盖前一日出清数据 |
| 14:10 | 行情 | 盘中刷新 |
| 23:10 | 行情 | 覆盖 22 点前的现货出清披露 |
| 每月1日 07:30 | 中长期 | 月度数据 |

### 4.3 输出格式

**SQLite**：`data/gd_power.sqlite`

| 表名 | 内容 |
|---|---|
| `fact_spot_hourly` | 24点逐时价格 |
| `fact_city_peakvalley` | 21市峰谷价 |
| `fact_daily_price` | 日度汇总（均价/峰谷均价/负价小时数） |
| `fact_midlong_year` | 年度中长期交易 |
| `fact_weather` | 气象（100m风速/辐照/温度） |
| `raw_snapshot` | 原始 JSON 存档（防解析错误，可重放） |
| `collect_log` | 采集日志 |

**CSV**：`output/*.csv`（UTF-8 BOM，Excel 直接打开不乱码）

**MySQL**：如需入库 MySQL，用 `schema.sql`：
```bash
mysql -u root -p < schema.sql
```

## 六、能采什么、不能采什么

### ✅ 已覆盖（免登录的「公众信息」层）

- 现货逐时价格、每日均价
- 21 个地市峰谷节点电价
- 中长期年度交易均价与电量

### ❌ 采不到（属「公开信息」层，需市场主体账号）

- 负荷预测（6.43）
- 分电源出力（6.48/6.51）
- 机组台数（6.58）
- 检修计划（6.31）
- 必开必停（6.37）

**接入方式**：注册成为市场主体后，用 `--headed` 模式手动登录一次，然后：

```python
# 在 portal.py 中保存登录态
sess.state_save("state/auth.json")
```

之后启动时传入 `storage_state="state/auth.json"`，即可在登录态下访问公开信息层数据。**这部分需要你自己验证权限——账户权限只有你能试。**

## 七、排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 接口返回 400 空 body | 缺 WAF 签名参数 | 必须走浏览器方案，别直接调 |
| 采集到 0 条 | 页面改版 / 接口改名 | 看 `logs/*.png` 截图，对照 `raw_snapshot` 表 |
| 浏览器启动失败 | 缺系统库 | `playwright install-deps chromium` |
| 中文乱码 | CSV 无 BOM | 已是 `utf-8-sig`，Excel 应正常 |
| 被限流/封禁 | 请求过频 | 调大 `.env` 里 `MIN_DELAY`/`MAX_DELAY` |

**合规提醒**：本采集器只获取免登录可见的公开行情数据，请求频率控制在**每日数次**，不爬取需授权的内容。请勿删掉延时逻辑或提高并发——那会触碰反爬红线。
